① Authored world：目前的航海圖

Port 與 navigation point 共用同一個 node id namespace。粗實線是海上 passage edge，灰色虛線是 Port 與其 harbor approach 之間的 berth edge。所有線在 content 中其實都是一去一回兩條 directed edges；這張人類圖把成對方向合併顯示。

最重要的拓樸特性：經過 Faro 附近不等於靠港 Lisbon → Tangier 會走過 faro-approach，但路徑不會進入 faro Port node。Planner 把 Port 視為 terminal：除了起點與最終目的地，其他 Port 都不能成為中繼節點。

④ passage-planner.ts：從意圖到穩定路徑

Planner 是 pure core computation。它不讀 React、不碰 IndexedDB，也不自行取得 Fleet state；caller 必須明確傳入 world、起訖 Port、known Ports 與 speed。

⑤ PassageQuote 的數值從哪裡來

輸出 公式 關鍵 rounding
Edge duration distance / speed × traversalModifier × 200,000 ms Edge 階段不取整。
Passage duration 所有 edge unrounded duration 加總 整段只做一次 Math.round。
Required Supply ceil(durationSeconds × 0.02)，Food／Water 各自計算 最終需求向上取整。
Static risk 1 - product(1 - edgeRisk) 不是直接把百分比相加。
Debug duration duration / 20 只影響 debug 觀察時間，不改正常 quote。
Passage Distance Normal Debug Food / Water Risk
